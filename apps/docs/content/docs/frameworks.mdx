---
title: Framework adapters
description: Use every Pixelshift tool through idiomatic React, Angular, and Vue APIs.
icon: Blocks
---

The adapters contain no image logic. They map each framework's properties, events, and refs onto the custom elements, so a tool behaves the same everywhere. Each adapter registers an element only when you import its component, so bundlers drop the tools you do not use.

## Components

| Tool                      | React               | Vue                 | Angular                                                          |
| ------------------------- | ------------------- | ------------------- | ---------------------------------------------------------------- |
| Image compressor          | `ImageCompressor`   | `ImageCompressor`   | `ImageCompressorComponent` · `<pixelshift-image-compressor>`     |
| Image resizer             | `ImageResizer`      | `ImageResizer`      | `ImageResizerComponent` · `<pixelshift-image-resizer>`           |
| Image converter           | `ImageConverter`    | `ImageConverter`    | `ImageConverterComponent` · `<pixelshift-converter>`             |
| Image cropper             | `ImageCropper`      | `ImageCropper`      | `ImageCropperComponent` · `<pixelshift-image-cropper>`           |
| Color picker              | `ColorPicker`       | `ColorPicker`       | `ColorPickerComponent` · `<pixelshift-color-picker>`             |
| Image to Base64           | `ImageToBase64`     | `ImageToBase64`     | `ImageToBase64Component` · `<pixelshift-image-to-base64>`        |
| Social media resizer      | `SocialResizer`     | `SocialResizer`     | `SocialResizerComponent` · `<pixelshift-social-resizer>`         |
| YouTube thumbnail resizer | `YouTubeThumbnail`  | `YouTubeThumbnail`  | `YouTubeThumbnailComponent` · `<pixelshift-youtube-thumbnail>`   |
| Background remover        | `BackgroundRemover` | `BackgroundRemover` | `BackgroundRemoverComponent` · `<pixelshift-background-remover>` |
| Studio                    | `PixelshiftStudio`  | `PixelshiftStudio`  | `PixelshiftStudioComponent` · `<pixelshift-studio>`              |

Every component accepts the shared properties (`disabled`, `isDarkMode`, `bare`, `auto`, `heading`, `description`, `locale`, `messages`) plus its tool's own properties from [Tools](/docs/tools), written in camelCase.

Each adapter also re-exports `registerLocale`, `ar`, and `en` — see [Localization & RTL](/docs/i18n).

In Angular, the tool components use the custom element's own tag as their selector: Angular creates the element itself and forwards inputs to it, so there is no wrapper node and the markup matches plain HTML. The converter keeps its original `<pixelshift-converter>` wrapper selector.

## Events

| Purpose             | React               | Vue template        | Angular             |
| ------------------- | ------------------- | ------------------- | ------------------- |
| Files selected      | `onFilesSelected`   | `@files-selected`   | `(filesSelected)`   |
| Processing started  | `onProcessStart`    | `@process-start`    | `(processStart)`    |
| Processing finished | `onProcessComplete` | `@process-complete` | `(processComplete)` |
| A file failed       | `onProcessError`    | `@process-error`    | `(processError)`    |
| Crop box moved      | `onCropChange`      | `@crop-change`      | `(cropChange)`      |
| Color picked        | `onColorPick`       | `@color-pick`       | `(colorPick)`       |
| Studio tab changed  | `onToolChange`      | `@tool-change`      | `(toolChange)`      |

React handlers receive the `CustomEvent`, so the payload is `event.detail`. Vue and Angular handlers receive the payload directly.

The converter also keeps its original events:

| Purpose             | React                  | Angular              | Vue template           |
| ------------------- | ---------------------- | -------------------- | ---------------------- |
| Conversion started  | `onConversionStart`    | `conversionStart`    | `@conversion-start`    |
| Conversion finished | `onConversionComplete` | `conversionComplete` | `@conversion-complete` |
| Conversion failed   | `onConversionError`    | `conversionError`    | `@conversion-error`    |

Tool events bubble, so a handler on the studio hears every tool inside it.

## React

```bash
pnpm add pixelshift-react
```

```tsx
import { useRef } from "react";
import {
  ImageCompressor,
  PixelshiftStudio,
  type ImageCompressorElement,
} from "pixelshift-react";

export function Upload() {
  const compressor = useRef<ImageCompressorElement>(null);

  return (
    <>
      <ImageCompressor
        ref={compressor}
        quality={0.75}
        targetSize={200 * 1024}
        multiple
        onFilesSelected={(event) => console.log(event.detail)}
        onProcessComplete={(event) => console.log(event.detail)}
        onProcessError={(event) => console.error(event.detail.error)}
      />

      <button type="button" onClick={() => void compressor.current?.process()}>
        Compress programmatically
      </button>
      <button type="button" onClick={() => compressor.current?.reset()}>
        Reset
      </button>
    </>
  );
}

export function Toolkit() {
  return (
    <PixelshiftStudio
      tools="compress,resize,crop,colors"
      onToolChange={(event) => console.log(event.detail)}
    />
  );
}
```

The converter's original React API still works: `<ImageConverter format="webp" onConversionComplete={...} onConversionError={...} />`.

## Angular

```bash
pnpm add pixelshift-angular
```

Import the standalone components, then use their typed inputs and outputs:

```ts
import { Component, ViewChild } from "@angular/core";
import {
  ImageCompressorComponent,
  ImageConverterComponent,
  type CompressionResult,
  type ConversionResult,
} from "pixelshift-angular";

@Component({
  selector: "app-upload",
  standalone: true,
  imports: [ImageCompressorComponent, ImageConverterComponent],
  template: `
    <pixelshift-image-compressor
      [quality]="0.75"
      [multiple]="true"
      (processComplete)="onCompressed($event)"
      (processError)="onFailed($event.file, $event.error)"
    />

    <pixelshift-converter
      format="webp"
      [quality]="0.85"
      [maxWidth]="2400"
      [multiple]="true"
      (conversionComplete)="onConverted($event)"
      (conversionError)="onError($event)"
    />
  `,
})
export class UploadComponent {
  @ViewChild(ImageCompressorComponent)
  private compressor?: ImageCompressorComponent;

  onCompressed(results: CompressionResult[]): void {
    console.log(results);
  }

  onConverted(results: ConversionResult[]): void {
    console.log(results);
  }

  onFailed(file: File, error: unknown): void {
    console.error(file.name, error);
  }

  onError(error: unknown): void {
    console.error(error);
  }

  compress(): void {
    void this.compressor?.process();
  }

  reset(): void {
    this.compressor?.reset();
  }
}
```

Tool components expose `process()`, `cancel()`, `reset()`, `loadFiles()`, and an `element` getter for the underlying custom element. `ImageConverterComponent` exposes `convert()` and `reset()`.

## Vue

```bash
pnpm add pixelshift-vue
```

```vue
<script setup lang="ts">
import { ref } from "vue";
import {
  ImageCompressor,
  ImageConverter,
  type CompressionResult,
  type ConversionResult,
} from "pixelshift-vue";

type ToolHandle = {
  process(): Promise<unknown[]>;
  reset(): void;
};

const compressor = ref<ToolHandle | null>(null);

function onCompressed(results: CompressionResult[]) {
  console.log(results);
}

function onConverted(results: ConversionResult[]) {
  console.log(results);
}

function onError(error: unknown) {
  console.error(error);
}
</script>

<template>
  <ImageCompressor
    ref="compressor"
    :quality="0.75"
    multiple
    @process-complete="onCompressed"
  />

  <ImageConverter
    format="webp"
    :quality="0.85"
    :max-width="2400"
    multiple
    @conversion-complete="onConverted"
    @conversion-error="onError"
  />

  <button type="button" @click="compressor?.process()">Compress</button>
  <button type="button" @click="compressor?.reset()">Reset</button>
</template>
```

Vue components expose `process()`, `cancel()`, `reset()`, `loadFiles()`, and `element` on their template ref. Props you leave out are not forwarded, so each element keeps its own defaults.

All three adapters re-export the result types (`ImageResult`, `CompressionResult`, `ConversionResult`, `ColorInfo`, `Base64Result`, `SocialResizeResult`, `BackgroundRemovalResult`, and more). The React and Vue packages also re-export the element classes, such as `ImageCompressorElement`.
